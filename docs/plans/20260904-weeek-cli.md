# weeek-cli v1: zero-dependency Go CLI для Weeek API + плагин Claude/Codex

## Overview

CLI `weeek` на Go для публичного API Weeek (task manager + workspace) и плагин со скиллом для Claude Code и Codex. Основной потребитель CLI — AI-агенты: стабильный JSON-вывод, предсказуемые флаги, коды ошибок. Человек пользуется через `jq`.

Решаемая проблема: у агентов нет удобного способа работать с Weeek (MCP-сервера нет, а REST руками агент зовёт неохотно и с ошибками). Тонкий CLI 1:1 к API + скилл с инструкциями закрывают это одним бинарником.

Интеграция: репозиторий сам является маркетплейс-плагином для обоих тулов (Claude Code: `/plugin marketplace add <owner>/weeek-cli`; Codex: `codex plugin marketplace add <owner>/weeek-cli`).

## Development Approach

- **testing approach**: Regular (код → сразу тесты к нему)
- Задачи выполнять последовательно, каждая — законченный логический юнит
- **Каждая задача обязана заканчиваться написанием/обновлением тестов**, и все тесты должны проходить до перехода к следующей
- Вывод CLI — контракт для агентов: golden-тесты фиксируют JSON-вывод, изменения вывода — только осознанно (major/minor)
- Zero зависимостей: только stdlib (`flag`, `net/http`, `encoding/json`, `os`, `time`). Ни cobra, ни yaml, ни генераторов
- Ответы API проходят на stdout как есть (`json.RawMessage`), типизируем только запросы, ошибки и «me»-резолв
- Обратная совместимость не актуальна (v1 с нуля), но формат вывода меняем только через фиксацию golden-тестов

## Testing Strategy

- **unit-тесты** (обязательны в каждой задаче):
  - `internal/api` — против `httptest.Server` с фейковыми ответами: успех, 401/404/429/5xx, ретраи, билд query-параметров
  - `internal/commands` — golden-тесты: фикстура-ответ → эталонный JSON на stdout; ошибки → эталонный stderr + exit code
  - `internal/auth` — приоритет env → конфиг, отсутствие обоих, права на файл 0600
- **механика golden-тестов**: эталоны лежат в `testdata/` рядом с тестом (`internal/commands/testdata/<command>.golden`); регенерация — `GOLDEN_UPDATE=1 go test ./...`; фикстуры API-ответов — `internal/api/testdata/*.json`; изменения эталона = осознанное изменение контракта, фиксировать в коммите отдельно
- **e2e/UI-тестов нет** (CLI без UI); их роль закрывают golden-тесты команд
- Живой API — только ручной смоук (см. Post-Completion), токен в CI не попадает

## Solution Overview

Тонкий CLI (выбранный подход «A» из брейншторма): команды noun-verb 1:1 к REST, JSON на stdout, ошибки однострочным JSON на stderr, exit codes 0/1/2. Вся «умность» — в скилле (markdown, правится без пересборки). Устройство:

- `cmd/weeek/main.go` — резолв токена → клиент → диспетчер команд
- `internal/api` — HTTP-ядро (авторизация, таймаут 30с, GET-ретраи 429/5xx до 2 раз с backoff 500мс/2с; записи без ретраев) + по файлу на домен
- `internal/auth` — `WEEEK_TOKEN` env → `~/.config/weeek/config.json` (chmod 600)
- `internal/commands` — таблица диспетчеризации `"task list" → Command{FlagSet, Run}`; интерсперсед-парсер флагов (~15 строк); usage-листинг из реестра
- `plugin/` — один скилл + два манифеста; в корне репо два marketplace.json

Ключевые решения: zero-dep (потребитель — агент, ему SKILL.md вместо `--help`); pass-through ответов (не гадаем структуры); плагин для обоих тулов из одного репо; сборка Makefile + `go build` (CGO_ENABLED=0), релизы бинарниками GitHub Releases.

## Technical Details

- **Диспетчеризация**: `map[string]Command`, ключ — полный путь (`"task comment add"`). Точное совпадение; промах → exit 2 со списком похожих команд (префиксный поиск)
- **Флаги**: stdlib `flag.FlagSet` на команду; хелпер `parseAll` циклит `fs.Parse` по остатку аргументов, чтобы работал и порядок `ID --flag x`, и `--flag x ID`
- **Контракт вывода**:
  - stdout: JSON ответа API как есть (для `me` — сборка `{"user": {...}, "workspace": {...}}` из двух RawMessage)
  - stderr при ошибке: `{"error":"<message>","status":<http|0>}` одной строкой; все сообщения на английском
  - exit: 0 — ок; 1 — ошибка API/сети/токена; 2 — неверное использование (bad flags, unknown command)
- **«me»-резолв**: значение `me` у `--responsible` → `GET /user/me` → ID. Минимальная типизация `struct{ ID int64 \`json:"id"\` }` — сверить имя поля на смоуке (догадка: `id`, camelCase подтверждён другими полями API)
- **Ретраи**: только GET, только 429/5xx, пауза 500мс → 2с, всего 2 повтора
- **Таймаут upload**: глобального таймаута 30с не хватает для вложений до 100MB на медленном канале — для POST вложений per-request таймаут увеличенный или отключённый
- **Конфиг**: фиксированный путь `~/.config/weeek/config.json` (через `os.UserHomeDir()/.config/weeek/`; именно `~/.config`, НЕ `os.UserConfigDir()` — на macOS тот даёт `~/Library/Application Support`, что отклоняется от согласованного дизайна и менее предсказуемо в текстах скилла/README); содержимое `{"token":"..."}`, запись с правами 0600
- **Тела create/update**: поля по спеке доков (title, description, priority, responsible, dueDate и т.п. — точные имена полей сверить на смоуке, camelCase); неизвестные поля API в ответах не теряются благодаря pass-through
- **Версия**: `var version = "dev"` в main, Makefile проставляет `-ldflags "-X main.version=$(git describe --tags)"`
- **Module path**: `github.com/<owner>/weeek-cli` — владельца репо проставить в задаче 1 (placeholder `<owner>`)
- **Плагин**:
  - `plugin/.claude-plugin/plugin.json` — манифест Claude Code, skills → `./skills/`
  - `plugin/.codex-plugin/plugin.json` — манифест Codex, `skills: "./skills/"`, поля `name/version/description`
  - `plugin/skills/weeek/SKILL.md` — frontmatter (`name: weeek`, `description` двуязычная RU+EN с триггер-словами: задачи/таски/доска/спринт/task/board/sprint/weeek), тело ~100–150 строк на английском: проверка окружения (`weeek me`, при 401 → подсказка про `WEEEK_TOKEN`/`weeek auth login`), паттерн «сначала list с фильтрами → взять ID → действие, ID не выдумывать», канонический порядок флагов, шпаргалка частых команд, ссылки на references
  - `plugin/skills/weeek/references/{tasks,boards,projects,workspace}.md` — полные флаги, примеры, сценарии (агент грузит по необходимости)
  - `.claude-plugin/marketplace.json` и `.agents/plugins/marketplace.json` в корне репо; в Codex-версии обязательны `policy.installation` и `policy.authentication`, source — путь `./plugin`
- **CI**: GitHub Actions; push/PR — `go vet ./...` + `go test ./...`; тег `v*` — матрица darwin/linux × amd64/arm64, `gh release create` с бинарниками из `dist/`
